# IWP 기반 Lookahead와 제약 관리

## 요약

- Lookahead의 단위를 Activity에서 IWP로 전환. 제약 해소된 IWP만 현장 배포
- 주간 회의의 목적 전환 : 진도율 설명 → "어느 IWP가 무엇 때문에 실행 불가, 누가 언제 해소"의 결정
- 출처 : [[원전 건설 AWP 적용 계획]], [\[a\] 원전 건설 AWP 도입 계획](../../1%20기획·입찰%20단계/1-5%20공사%20수행전략%20수립/AWP/%5Ba%5D%20원전%20건설%20AWP%20도입%20계획.md), [[AWP Advanced Work Packaging|AWP 문헌·사례 읽기 가이드]]의 해당 부분 발췌·재구성

## 1. IWP 배포 전 제약 확인 항목

| 구분 | 확인 내용 |
|---|---|
| 설계 | 최신 개정 도면, 해당 범위 시공용 발행 여부, Vendor Data 반영 |
| 자재·기기 | 해당 IWP용 배정 완료 (구매 완료와 구분) |
| 선행 작업 | 선행 CWP·IWP 완료 |
| 장비·비계·접근 | 장비 배정, 비계, 작업 공간 |
| 품질·인허가 | ITP Hold Point, 규제기관 검사, 은폐 작업 전 검사 |

- "패키지 작성 완료"와 "실행 가능" 상태 분리
- EWP 발행 완료 ≠ 작업 가능 상태

## 2. 운영 주기

| 주기 | 내용 |
|---|---|
| 주간 | 다음 작업의 설계·자료·자재·작업 준비 확인 |
| 주간 | 발주자·설계·구매·시공 제약 해소 회의 |
| 상시 | 제약 해소 IWP Backlog 2~4주분 유지 |
| 사건 발생 시 | Event 등록·통지·영향 분석 |
| IWP 완료 시 | 실제 공수·지연 원인·품질 기록·교훈 회수 |

- 참고 사례 (Qatar NFE LNG) : 6개월 전망, 90일 제약·자원 가시성, 동적 IWP Release Plan

## 3. 우회 작업의 기록

- Block-out 등 우회 작업은 "임시조치 IWP"로 별도 등록
- 추가 작업·재작업 공수·지연 원인 책임이 공정표에 잔존
- 우선 진행으로 발생한 지연·재작업이 공정표와 비용에서 사라지지 않게 관리

## 4. 지연분석과의 연결

- IWP 발행 이력과 Constraint Log = "언제 무엇이 준비되지 않아 착수하지 못했는가"의 동시대 기록(Contemporaneous Record)
- 클레임·포렌식 관점에서 증거 생성 체계
