# 공정관리계획서의 AWP 반영 항목

## 요약

- AWP 적용 프로젝트에서 공정관리계획서에 사전 규정할 항목
- 핵심 : 코드 체계, 공정표 Level 구조, 책임 주체 코드, 필요일 역산 규칙, 업데이트·Event 절차, 측정 지표
- 출처 : [[원전 건설 AWP 적용 계획]], [[원전 건설 AWP 도입 계획]]의 해당 부분 발췌·재구성

## 1. 코드 체계

| 항목 | 규정 내용 |
|---|---|
| CWA | 기존 Zoning을 코드화. 시공의 공간적 관리축 |
| CWP | CWA × 공종 × 레벨 구간 (예: AB-Z3 EL.100~120 구조체) |
| IWP | 작업반 실행 단위 |
| System | 기능·시험·인수인계 관리축. Zone과 병행 유지 |
| 부여 방법 | P6 Activity Code·UDF<sup>1</sup>. 이후 모든 연결의 기준 키 |

## 2. 공정표 Level 구조

| Level | 구성 |
|---|---|
| Level 3 | EWP·PWP·CWP를 FS 관계 Activity로 연결 |
| Level 4 | IWP 1개 = Activity 1개 |

- 모든 인터페이스 노드에 책임 주체 코드 부여 : Owner / Contractor / Vendor / Designer
- 검토·제작·검사 등 관리 가능한 업무는 Lag 대신 명시적 Activity로 표현. 고정 착수일로 연결 부족을 덮지 않음

## 3. 필요일 역산 규칙

| 대상 | 역산 기준 |
|---|---|
| EWP 필요일 | CWP 착수일 − IWP 준비기간 (예: 60~90일) |
| Vendor Data 필요일 | EWP 필요일 − 설계 반영·검토·승인 기간 − 제출·재제출 기간 |
| ROS<sup>2</sup> | IWP 착수일에서 역산. 발주자에게 공식 문서로 통보, 통보 이력 = 증빙 |

- 기간은 실제 업무량과 과거 처리 실적 기준. 일률적 "착수 4주 전" 적용 금지

## 4. 업데이트·변경·Event 절차

| 항목 | 규정 내용 |
|---|---|
| 업데이트 주기 | 월간 또는 합의한 더 짧은 주기의 공식 업데이트 |
| 버전 관리 | 기준공정표·업데이트 원본 보존. 과거에 없던 선행관계의 소급 작성 금지 |
| Event 등록 | 발생·인지·통지일, 근거 문서, 관련 PO·Tag·도면, 영향 패키지, 대응 책임자 |
| 사건 직전 일정 | 당시 업데이트 원본, 실제 진도, 잔여기간, 선행관계, 설계·납품 예측 근거 보존 |
| 영향 보고 | 대응 전 영향과 완화대책 후 잔여 영향 구분. 미확정 입력은 시나리오로 표시 |

## 5. 측정 지표

- EWP 적기 발행률
- Certified Vendor Data 적기 확보율
- 제약 해소 IWP Backlog (2~4주분)
- Block-out 발생 건수
- Event 인지 → 최초 영향 분석 소요시간

> [!note] 주석
> 1. UDF(User Defined Field): P6 사용자 정의 필드
> 2. ROS(Required On Site): 시공에 필요한 현장 입고 요구일
