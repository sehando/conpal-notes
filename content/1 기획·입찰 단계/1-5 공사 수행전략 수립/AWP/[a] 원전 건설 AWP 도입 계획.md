> 기존 Zoning과 공종별 시공 순서를 출발점으로, 설계·발주자 구매·Vendor Data를 시공 필요 시점에 연결하는 최초 도입 계획이다. 약 6개월의 기간과 패키지 수는 제안값이며, 실제 계약·공정표·설계 및 구매 현황을 검토한 뒤 조정해야 한다. 특정 프로젝트의 확정 공정계획이나 법률 의견은 아니다.

## 핵심 방향

필요한 것은 기존 Zoning을 새로 만드는 것이 아니라, 이미 정교하게 계획한 시공 순서를 설계·발주자 구매·Vendor Data의 요구 일정으로 역산해 연결하는 것이다.

상정하는 현재 상태는 다음과 같다.

- 현장은 Zone과 공종별 순서를 정해 간섭을 줄이고 순차 시공을 수행한다.
- 설계는 단위 Level별 도면 발행일을 관리하지만 Zone별 시공 필요와의 연결은 부족하다.
- 구매 기기정보가 필요한 설계의 별도 관리 포인트가 없다. 앵커볼트 정보 미확보로 Block-out 후 진행하는 일이 발생한다.
- 발주자가 직접 구매하며, 구매 지연의 영향과 위험이 시공사에 집중돼 왔다.
- 구매 일정에는 최초·최종 Delivery만 반영돼 실제 사용 단위의 준비 상태를 알기 어렵다.
- 사용자 변경·공급업체 사정 등의 Event는 별도 상세 분석을 해야 후속 영향을 확인할 수 있다.

현장 시공의 최적화와 별개로, **그 작업을 언제 실행할 수 있게 만들 것인가**에 대한 상위 역무의 연결이 필요하다. 다음 세 가지를 함께 도입한다.

1. **AWP:** 시공 Activity에 필요한 설계·기자재·정보·작업 조건을 연결한다.
2. **통합 일정·변경관리:** 지연 사건의 후속 작업 및 주요 마일스톤 영향을 계산한다.
3. **인터페이스·계약·증빙관리:** 누가 무엇을 제공하기로 했고, 무엇 때문에 지연됐는지를 당시에 남긴다.

**AWP만 도입한다고 계약상 위험이 재배분되지는 않는다.** 발주자 직접 구매 구조에서는 통합 일정과 인터페이스·계약·증빙관리가 빠지면, 시공사는 더 상세한 패키지를 작성하면서도 종전과 같은 위험을 부담할 수 있다.

## 1. 적용 목표와 기본 구조

2025년 한국원자력학회 발표자료도 기존 원전 프로젝트의 공종 중심 설계, PO 중심 구매, 시공 중심 일정 사이의 연결 부족을 지적하고, CWA·EWP·PWP·CWP를 연결하는 WBS 보완을 제안한다.[1] 이는 도입 모델에 관한 연구이지 원전 공기 단축의 검증된 실적은 아니다.

설계 조직·구매계약·기존 WBS를 처음부터 전면 재편하지 않는다. **기존 체계를 유지하면서 공통 식별자와 연결 관계를 먼저 추가**한다.

| 관리 대상 | 상정하는 현재 방식 | 추가할 연결·완료 기준 |
| --- | --- | --- |
| 시공 | Zone·공종별 순서 | 기존 Activity에 CWA·CWP·IWP와 필요 산출물 연결 |
| 설계 | 단위 Level별 도면 발행 | 각 CWP를 지원하는 승인 산출물 묶음과 필요 시점 관리 |
| 기기정보 | 별도 관리 포인트 없음 | Vendor Data 제출·설계 검토·사용 가능 상태 구분 |
| 구매·납품 | 최초·최종 Delivery | Tag·Lot별 현장 사용 가능 시점과 소비 작업 연결 |
| 지연·변경 | 사후 별도 분석 | Event별 영향 경로·일정 버전·당시 증빙 보존 |

- **CWA:** 시공의 공간적 구역.
- **CWP:** 일정한 경계의 시공 범위.
- **EWP:** 그 시공 범위를 지원하는 통제된 설계 산출물 묶음.
- **PWP 및 구매 연결:** 구매·제작·납품의 산출물과 시공 사용 단위의 관계.
- **IWP:** 실제 작업반이 실행할 단위이며, 작업 준비 조건의 확인 대상.

**Zone은 시공의 공간적 관리축이고, System은 기능·시험·인수인계의 관리축이다.** 두 축을 함께 유지한다. Zone 공사가 끝났다고 해당 계통이 시운전 가능한 것은 아니다.

## 2. 단계별 도입 계획

### 단계 0. 발주자·설계자·시공사의 운영 합의: 1~2주

가장 먼저 할 일은 소프트웨어 구매가 아니라 **발주자 참여와 인터페이스 합의**다.

합의할 사항:

- 파일럿 범위와 공통 공정표.
- 시공 필요 시점의 작성·검토·확정 방법.
- 발주자 구매 담당자가 제공할 일정·Vendor Data·납품 상태.
- 설계자의 자료 검토·설계 반영·승인 책임.
- 일정 업데이트 주기와 변경 승인 절차.
- 지연 통지, 영향 분석, 회복대책 및 비용 처리 절차.
- 기존 계약상 권리·의무와 이미 발생한 지연의 처리.

운영 역할:

| 역할 | 주요 책임 |
| --- | --- |
| 발주자 책임자 | 설계·구매·시공 간 우선순위와 회복대책 의사결정 |
| 통합 일정 담당 | 선행관계, 업데이트, 영향 분석, 버전관리 |
| 설계 인터페이스 담당 | EWP와 Vendor Data의 적합성·승인 상태 |
| 발주자 구매 담당 | 공급업체 약속, 제작·납품·자료 제출 추적 및 독촉 |
| Superintendent·WorkFace Planner | 실제 실행 순서, IWP, 작업 준비 |
| 품질·설계권한 조직 | 원전 품질 확인 및 설계·형상 변경 통제 |

시공사가 공급업체와 직접 계약하지 않았다면 공급업체에 대한 계약상 이행 요구는 발주자 구매 조직이 수행한다. 시공사는 영향 확인과 실행대안을 검토하되, 구매 일정 통제 책임까지 사실상 넘겨받지 않는다.

발주자 지급·시공사 설치 방식인 OFCI에 관한 NAC 자료도 이 구조가 추가 인터페이스를 만들며, 설계·구매·시공의 책임 경계와 변경·지연 처리의 불명확성이 분쟁 위험을 높인다고 설명한다.[2]

**완료 산출물:** 공동 AWP 실행계획, 역할·책임표, 일정·자료 제공 규칙, 인터페이스 합의서.

### 단계 1. 기존 시공 계획을 패키지 구조로 연결: 3~4주

#### 파일럿 선정

향후 약 6개월 내 실행할 한 구역에서, 기기기초부터 기기 설치·연결 공사까지 이어지는 범위를 선정한다.

제안 규모:

- CWA 1개.
- 기초·기기 설치·연결 배관 등의 CWP 3~5개.
- 작업반 실행 단위 IWP 10~20개.

앵커볼트 정보, 발주자 구매, 설계 반영, 현장 납품이 모두 들어 있어야 문제를 검증할 수 있다. 이미 완료된 공사를 패키지로 다시 포장하는 것은 첫 파일럿의 우선순위가 아니다.

#### Activity별 연결 작업

- CWA·CWP·IWP.
- 건물·층·Zone.
- 관련 System·기기 Tag.
- 필요한 도면·계산서·시방서 및 승인 개정번호.
- 필요한 Vendor Data.
- 필요한 자재·기기·Lot·수량.
- 선행 작업·접근·장비·품질 확인 조건.

기존 Activity를 모두 분해할 필요는 없다. 다만 한 Activity 안에 서로 다른 설계·자재 조건 때문에 착수 시점이 달라지는 작업이 섞여 있다면 분리한다.

**완료 산출물:** 패키지 경계도, Activity–산출물 연결표, 파일럿 시공 경로.

### 단계 2. 설계·구매 연결 및 통합 일정 구축: 2개월 차

다음 3~5절의 방법으로 EWP, Vendor Data, 납품을 시공 일정에 연결한다. 과거 날짜와 현재 상태를 정직하게 구분한다.

- 기존 기준공정표 및 업데이트 이력을 보존한다.
- 이미 진행된 설계·구매·입고의 실제 상태를 확인한다.
- 현재 시점의 연결된 예측 일정을 작성한다.
- 새로 합의하는 기준과 적용 범위를 명시한다.
- 과거에 없었던 선행관계를 당초부터 합의된 계획처럼 소급 작성하지 않는다.

**완료 산출물:** 연결된 통합 공정표, EWP release plan, Vendor Data 목록, Tag·Lot별 납품 계획, 제약 목록.

### 단계 3. 파일럿 운영: 3~4개월 차

- **주간:** 다음 작업의 설계·자료·자재·작업 준비 확인.
- **주간:** 발주자·설계·구매·시공 제약 해소 회의.
- **월간 또는 합의한 더 짧은 주기:** 공식 일정 업데이트와 영향 보고.
- **사건 발생 시:** 별도 Event 등록·통지·영향 분석.
- **IWP 완료 시:** 실제 공수·지연 원인·품질 기록·교훈 회수.

회의는 전체 진도율을 설명하는 방식보다 **어느 IWP가 무엇 때문에 실행 불가능하고, 누가 언제 해소할 것인가**를 결정하는 방식으로 바꾼다.

### 단계 4. 검증·확대: 5~6개월 차

다음 조건을 충족한 뒤 인접 구역·다른 공종으로 확대한다.

- 주요 시공 작업의 설계·구매 선행관계가 연결됐다.
- 필요한 Vendor Data와 자재 상태가 증빙으로 확인된다.
- 실제 변경 사건에 대해 후속 영향이 재현된다.
- 패키지 작성 부담과 현장 효과를 평가했다.
- 미해결 계약·자료 제공 문제를 개선했다.

첫 파일럿의 성공 기준은 공기 단축률보다 **연결의 정확성, 조기 경보, 실행 준비, 기록의 신뢰성**으로 잡는다.

## 3. 기존 도면 발행 관리를 EWP 관리로 바꾸는 방법

모든 도면을 Zone별로 다시 그릴 필요는 없다. EWP를 **특정 CWP가 필요로 하는 통제된 설계 산출물의 묶음**으로 정의한다.

한 층의 구조도면이 여러 Zone을 포함한다면:

- 도면 원본과 개정관리는 하나로 유지한다.
- 그 도면이 지원하는 CWP들을 연결한다.
- 각 CWP에 필요한 상세도·Vendor Data·미결사항을 별도로 식별한다.
- 해당 범위의 시공 가능 여부를 설계권한 조직이 판단한다.

하나의 EWP나 공통 설계 산출물이 여러 CWP를 지원하는 관계도 허용한다. 숫자를 맞추기 위해 도면을 복제하지 않는다.

### EWP에서 구분할 상태

1. 작성 중.
2. 필요한 입력자료 미확보.
3. 설계 검토·승인 중.
4. 해당 범위 시공용 산출물 발행 완료.
5. 변경 때문에 해당 범위 사용 재검토 필요.

**도면 발행 완료가 미결 조건 없이 현장 사용 가능을 뜻하는지 확인**한다. 조건부 발행, 특정 범위 제외, Vendor Data 미반영 등을 감추지 않는다.

### 필요 시점 역산

- IWP 착수에서 패키지 준비·현장 검토 기간을 역산한다.
- 그 시점에서 설계 반영·검토·승인 기간을 역산한다.
- 다시 Vendor Data 제출·검토·재제출 기간을 역산한다.

기간은 실제 업무량과 과거 처리 실적으로 정한다. 모든 EWP에 일률적으로 착수 4주 전을 적용하지 않는다.

설계 단계 AWP 연구도 설계 공수 투입 시점을 앞당기고 EWP 단위 진도 인정 기준을 조정하는 필요성을 제시한다.[3] 전체 도면 진도율뿐 아니라 다음 시공 범위에 필요한 설계가 준비됐는지를 보고한다.

## 4. 구매를 납품과 설계 입력의 두 흐름으로 관리

### 4-1. Vendor Data를 독립적인 구매 산출물로 관리

기기 현장 납품보다 훨씬 먼저 필요한 정보:

- 앵커볼트 배치·규격·매입 관련 정보.
- 기기 하중·외형·유지보수 공간.
- 노즐 위치·연결 조건.
- 전력·단자·접속 정보.
- 배관·덕트·관통부 인터페이스.

이를 **PO별 Vendor Data Deliverable Register**로 관리한다. 각 항목의 최소 필드는 다음과 같다.

- PO·Tag·자료 ID.
- 영향을 받는 EWP·CWP·Activity.
- 공급업체 제출 약속일.
- 설계에서 필요한 시점.
- 검토·재제출·사용 가능 상태.
- 책임자·현재 예측일·승인 문서.

**자료를 받았다는 사실과 설계에 사용할 수 있다는 판단은 분리**한다.

기기 최종 제작승인을 기다리지 않고 기초 인터페이스를 먼저 확정할 수 있다면 활용하되, 공급업체·설계권한 조직이 인정한 통제된 인터페이스여야 한다. 미확정 수치를 현장에서 임의로 사용하지 않는다.

### 4-2. 최초·최종 Delivery를 Tag·Lot별 사용 가능 시점으로 상세화

기존 PO를 반드시 쪼개지는 않는다. 하나의 PO 안에서 현장 사용 단위의 납품 그룹을 정의한다.

예:

- A Zone 기기기초용 앵커·템플릿.
- B Zone 기기 설치용 본체·부속품.
- 특정 배관 IWP의 스풀·밸브·볼트·가스켓 묶음.

주요 품목은 다음 흐름을 추적한다.

1. 제작에 필요한 승인.
2. 제작 및 검사.
3. 출하 가능.
4. 운송·현장 도착.
5. 수입검사·문서 확인.
6. 해당 작업용으로 배정된 사용 가능 상태.

본체가 도착해도 설치 부속품이나 요구 품질문서가 없으면 설치 가능한 것은 아니다. 반대로 최종 납품이 끝나지 않아도 특정 IWP의 필요품이 모두 준비됐다면 그 범위는 실행할 수 있다.

발주자는 이 시공 필요 단위를 공급업체의 납품·자료 제공 계획과 연결하고, 필요 시 계약 변경 또는 별도 합의를 한다. 시공 필요 시점을 등록했다고 기존 공급업체 계약 의무가 자동 변경되지는 않는다.

## 5. 앵커볼트·Block-out 문제의 공정표 반영

기기 납품과 기초 설계 입력을 별도 선행 경로로 표현한다.

### 기초 공사에 필요한 정보 경로

- 발주자 구매·공급업체 선정.
- 기초 인터페이스 자료 제출.
- 설계 검토·보완 및 사용 가능 판단.
- 기초 계산·상세설계 반영.
- 해당 범위 시공용 도면 발행.
- IWP 준비·검토.

### 기초 공사에 필요한 자재 경로

- 앵커·템플릿 사양 확정.
- 제작·납품.
- 요구 검사·문서 확인.
- 해당 작업용 자재 배정.

이 두 경로에 선행 공사·작업 공간·검사 조건을 연결해야 기초 작업 준비 상태가 결정된다.

**일정에 날짜를 적는 것이 아니라 실제 종속 관계를 넣는 것**이 핵심이다. 검토·제작·검사처럼 관리할 수 있는 업무는 숨겨진 lag보다 명시적인 Activity로 표현하는 편이 좋다. 무조건적인 고정 착수일로 연결 부족을 덮지 않는다.

### 설명용 일정 예시

모든 기간을 달력일로 단순화하고, 나머지 조건은 동일하다고 가정한다.

- Vendor Data 사용 가능: D40.
- 그 뒤 설계·작업 준비 55일 필요: 해당 경로 준비 완료 D95.
- 다른 선행조건 준비 완료: D100.
- 기초 작업 착수: D100.

Vendor Data가 20일 늦어져 D60에 사용 가능해지면 해당 경로 준비 완료는 D115이고, 기초 작업 착수도 D115다. **이 작업의 착수 영향은 20일이 아니라 15일**이다.

프로젝트 준공일 영향은 해당 경로의 임계성, 다른 여유, 자원 및 후속 제약에 따라 달라진다. 이 예시는 실제 프로젝트 영향 분석 결과가 아니다.

### Block-out을 선택하는 경우

Block-out을 무조건 금지하지 않는다. 대신 승인된 대체 시공 전략으로 관리한다.

- 설계·구조·품질 영향 검토.
- 당초 일괄 시공과 대체안 비교.
- 나중의 앵커 설치·마감·검사·재접근 작업 등록.
- 추가 공수·비용·공간 점유와 후속 간섭 확인.
- 승인 및 시행 결정 기록.

우선 공사를 진행했다는 이유로 발생한 지연·재작업이 공정표와 비용에서 사라지지 않게 한다.

## 6. 변경·공급업체 부도 등의 Event와 증빙관리

논리 연결만 있으면 모든 사건의 영향이 자동으로 정확해지는 것은 아니다. 변경 내용, 새 처리 기간, 영향 범위의 입력과 검토가 필요하다. 다만 매번 연결 관계를 처음부터 찾아야 하는 부담을 크게 줄일 수 있다.

### ① Event 등록

- 발생·인지·통지 날짜.
- 사건 내용과 근거 문서.
- 관련 PO·Tag·도면·자료.
- 영향 가능 패키지.
- 대응 책임자.
- 계약상 책임은 합의 여부를 구분해 기록.

### ② 사건 직전 일정 보존

- 당시 업데이트 원본.
- 기준일, 실제 진도, 잔여기간, 선행관계.
- 당시 설계·납품 예측과 근거.
- 합의·미합의·미검증 입력의 표시.

### ③ 필요한 작업을 일정에 추가

최종사용자 변경이면 변경 검토·설계 수정·승인·재제작 등을 넣는다.

공급업체 부도라면 영향에 따라 다음 역무를 반영한다.

- 기존 제작품·자료 회수 가능성 확인.
- 대체업체 선정·자격 및 품질 확인.
- 재발주.
- 인터페이스 변경·재설계.
- 제작·시험·운송.

완료된 과거 Activity를 지우기보다 변경 사건 이후의 추가 역무를 별도 식별한다.

### ④ 영향과 대응안을 구분해 보고

- 영향받는 CWP·IWP.
- 착수·완료 및 주요 마일스톤 변화.
- 여유 소진.
- 대응 전 영향.
- 승인된 완화대책 적용 후 잔여 영향.
- 추가 비용·재작업·생산성 손실 가능성.

대체업체 납기 등이 미확정이면 단일 날짜를 확정값처럼 쓰지 않는다. 가정별 시나리오와 미확정 상태를 함께 표시한다.

### 증빙의 연결

각 Event에 다음 자료를 연결한다.

- 요구·약속·실제 자료 제공 및 납품 시점.
- 당시 공정표와 변경 사유.
- 제출·검토·반려 기록.
- 입고·검사·자재 배정 기록.
- 일일 작업, 인력·장비, 대기·재작업 기록.
- 의사결정, 통지, 회복지시.

SCL Delay and Disruption Protocol은 발주자 제공 정보·자재 인터페이스의 일정 연결, 당시 기록과 일정 업데이트 보존, 사건 직전 업데이트를 이용한 영향 평가 등을 권고한다.[4] 참고할 실무 지침이지 모든 계약·법체계에서 적용되는 법적 규칙은 아니다.

**중요한 구분:**

- 작업 지연과 준공 지연은 다르다.
- 공기연장과 추가비용 인정은 다르다.
- 구매 문제와 시공사 자체 제약이 동시에 있으면 별도 분석이 필요하다.
- 완화대책 시행과 계약상 권리 포기는 같은 뜻이 아니다.

AWP는 객관성을 높일 기반을 만들지만 청구권이나 책임 배분을 자동 결정하지 않는다.

## 7. 원전 특유의 통제와 성과 평가

### 원전에서 함께 설계할 통제

IAEA SSG-38은 시공에 필요한 통제된 설계·공급업체 정보, 검사·시험, 설계변경·부적합 관리, 추적성 및 인수인계 기록의 중요성을 설명한다.[5] IAEA의 원전 프로젝트 관리 지침도 AWP와 승인된 설계·자재 정보, 시스템별 인수인계의 연계를 다룬다.[6]

다음을 AWP에 통합한다.

- AWP 작업준비 승인과 규제·허가 승인 구분.
- 콘크리트 타설·은폐 작업 전 필요한 검사·Hold Point 관리.
- 안전 중요도 및 해당 품질 요구사항에 따른 기록·추적성.
- 대체품·Block-out·시공 변경의 설계권한 검토.
- 개정 도면, NCR 처리, As-built의 패키지 연결.
- Zone 완료와 System 인수인계 교차 연결.
- 자재 입고 이후 보존·관리 및 인수인계 책임.

패키지가 Ready여도 미해제된 해당 품질·규제 조건을 건너뛰지 않는다. 상세 요건은 해당 국가·허가·프로젝트 품질계획에서 확인한다. IAEA Safety Guide의 권고를 각 국가의 구체적 법적 의무와 동일시하지 않는다.

### 파일럿 평가 지표

- 주요 시공 Activity의 설계·자료·자재 연결률.
- 필요 시점까지 사용 가능 상태가 된 EWP·Vendor Data·자재 비율.
- 다음 작업의 미해결 제약과 실행 가능한 대체 작업 확보 수준.
- Vendor Data 미확보로 발생한 Block-out·재작업.
- Event 인지부터 최초 영향 분석까지의 시간.
- 당시 기록으로 재현 가능한 지연 사건 비율.
- 패키지 준비에 추가된 공수 대비 현장 대기·재작업 개선.

도면 발행 건수, 전체 입고율, 패키지 작성 건수만으로 성과를 평가하지 않는다.

## 무엇이 개선되고, 무엇은 남는가

개선할 수 있는 것:

- 설계가 늦었을 때 어느 구역의 어떤 작업이 막히는지 조기에 확인.
- 기기 납품 전부터 기초·관통부·배관·전기 설계 입력의 지연을 별도 관리.
- 최초·최종 Delivery 사이의 실제 사용 단위별 부족 식별.
- 변경·부도 사건 영향 분석을 위한 연결 관계와 당시 상태 확보.
- Block-out·작업 전환으로 흡수한 손실 가시화.
- 발주자 구매 약속과 시공 의존관계의 공통 기록 확보.

AWP만으로 공급업체 부도, 사용자 변경, 잘못된 위험 배분을 없애지는 못한다. **발주자의 자료 제공과 구매 이행 관리, 설계권한 조직의 참여, 계약·인터페이스 합의가 도입의 전제**다.

### 첫 30일에 확보할 다섯 가지

1. 파일럿 범위와 기존 시공 경로.
2. Activity–도면–Vendor Data–Tag·Lot 연결표.
3. 발주자 구매의 자료·납품 약속 및 확인 상태.
4. 현재 일정과 원본 이력의 보존·업데이트 규칙.
5. 제약·변경·지연 통지와 책임·의사결정 절차.

**결론:** 원전 최초 AWP 도입은 현장 작업패키지 작성보다 **시공 필요를 기준으로 발주자·설계자·공급업체의 제공 의무와 일정을 연결하는 체계**로 시작해야 한다. 그래야 현장 최적화의 효과가 상위 역무 지연 때문에 무너지지 않고, 발생한 영향과 비용도 당시에 추적할 수 있다.
